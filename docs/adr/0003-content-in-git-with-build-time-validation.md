# 0003. 콘텐츠와 관계 데이터는 Git의 파일로 두고, 빌드 시점에 검증한다

- 상태: 채택
- 날짜: 2026-08-26, 2026-10-11 보강

## 배경
글, 기술, 기술 간 관계, 트랙이 서로 참조한다. 참조가 하나 틀리면 깨진 링크나 빈 페이지가 생긴다. 이런 문제는 배포 후 방문자가 먼저 발견하기 쉽다.

## 결정
- 모든 데이터는 저장소의 Markdown/YAML이 원본이다. 같은 관계를 두 곳에 적지 않는다. 역방향(다음 기술, 기술별 글 목록)은 빌드 때 계산한다.
- 형식은 Content Collections 스키마(zod)로, 참조는 `src/lib/tech.ts`에서 검사한다. 다음 경우 **빌드를 실패**시킨다.
  - 없는 기술 ID를 글, 기술, 트랙에서 참조
  - 같은 기술 ID가 두 분야에 정의됨
  - `requires`가 순환함 (예: A → B → A)
  - 분야 색상이 `#rrggbb` 형식이 아님 (스타일 속성에 그대로 들어가기 때문)

## 검토한 대안
- **헤드리스 CMS / DB**: 편집 화면은 좋아지지만 서버나 외부 서비스가 생기고, 데이터와 코드의 버전이 따로 놀게 된다.
- **경고만 출력**: 빌드 로그를 보지 않으면 놓친다. 실제로 이전 구조에서는 연결이 빠져도 아무도 몰랐다.

## 결과
- 잘못된 데이터는 배포 전에 막힌다. 순환 참조와 없는 ID로 빌드가 실패하는 것을 직접 확인했다.
- 편집은 텍스트 에디터와 Git으로만 한다. 혼자 운영하므로 문제없다.
