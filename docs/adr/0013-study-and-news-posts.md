# 0013. 학습 글과 소식 글을 구분하고, 루틴은 소식 글만 쓴다

- 상태: 채택
- 날짜: 2026-10-11

## 배경
블로그는 기술 흐름을 따라 공부한 것을 기록하는 구조다([0004](0004-tech-flow-instead-of-graph.md), [0010](0010-curated-learning-tracks.md)). 그런데 예약 루틴이 쓰는 초안은 최근 뉴스(새 릴리스, API 변경) 해설이었다. 두 종류가 섞이면 문제가 생긴다.
- 뉴스 글이 몇몇 기술에 몰려 로드맵과 트랙 진행도가 실제 학습 정도와 다르게 보인다.
- 독자가 순서대로 공부한 글과 소식 해설을 구분할 수 없다.

## 결정
- 글 frontmatter에 `kind`를 둔다.
  - `study`(기본값): 직접 쓰는 학습 글
  - `news`: 소식 글
- 소식 글은 다음처럼 다룬다.
  - `/news/`에 모이고, 카드와 글 상단에 "소식" 배지를 붙인다.
  - 기술 허브에서는 "관련 소식"으로 따로 보여준다.
  - 로드맵·트랙 진행도와 학습 경로의 글 개수에는 **집계하지 않는다**.
- 학습 글은 직접 쓴다. 예약 루틴은 **직접 실습해 볼 수 있는 소식**(설치해 돌려 볼 수 있는 새 버전, API, 도구)만 `kind: news`로 `drafts` 브랜치에 쓴다.

## 검토한 대안
- **별도 저장소/사이트**: 완전히 분리되지만 배포와 디자인을 두 번 관리해야 한다.
- **루틴이 트랙 빈칸을 학습 글로 채우기**: 학습 글은 직접 공부하며 써야 의미가 있어 제외했다.

## 결과
- 진행도는 직접 공부한 것만 반영한다.
- 소식 글도 기술에 연결돼 기술 허브에서 찾을 수 있다. 소식만 있는 기술 페이지는 검색 제외(`noindex`)를 풀고 sitemap에 넣는다.
