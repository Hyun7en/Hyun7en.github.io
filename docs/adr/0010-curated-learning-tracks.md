# 0010. 자동 추천 경로 대신 직접 고른 학습 트랙을 둔다

- 상태: 채택
- 날짜: 2026-10-11

## 배경
홈의 "추천 학습 경로"는 글이 많이 쌓인 선행 관계 체인을 자동으로 골랐다. 그런데 기술 관계는 갈라지는 구조(DAG)라서, 자동 경로는 한 갈래만 보여주고 나머지를 버렸다. 예를 들어 Spring Data JPA로 가는 경로에서 JPA 갈래가 빠졌다. "이것 아니면 저것"(MySQL / PostgreSQL) 같은 선택지도 표현할 수 없었다. 이 부분은 roadmap.sh를 참고했다.

## 결정
- 트랙은 `src/content/tracks/<id>.yaml`에 직접 정의한다.
  - 중심 줄기(`steps`)의 각 단계는 기술 하나(`tech`) 또는 택1(`pick`)이다.
  - 곁가지(`with`)는 그 단계에서 함께 보면 좋은 기술이다.
- `/tracks/<id>/`는 세로 줄기 양옆에 가지를 번갈아 붙인다. 모바일에서는 줄기를 왼쪽에 두고 가지를 각 단계 아래에 둔다.
- 홈과 로드맵에 트랙 카드를 두고, 기술 허브에는 그 기술이 속한 트랙을 표시한다.
- 개별 기술의 갈라짐은 기술 허브와 글 상단의 학습 경로 트리가 보여준다.

## 검토한 대안
- **자동 경로 개선**: 갈래를 모두 보여주면 사실상 트리가 되어 홈 요약으로는 너무 크다. "택1"이나 "곁가지" 같은 의도는 데이터에서 추론할 수 없다.

## 결과
- 학습 순서라는 편집 의도가 드러나고, 택1과 곁가지를 구분할 수 있다.
- 트랙은 손으로 관리해야 한다. 없는 기술 ID는 빌드가 막아 준다([0003](0003-content-in-git-with-build-time-validation.md)).
- 시작 트랙 5개: Spring 백엔드, Node.js 백엔드, 프론트엔드, LLM 애플리케이션, DevOps.
