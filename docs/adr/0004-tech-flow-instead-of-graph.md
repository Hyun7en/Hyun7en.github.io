# 0004. Architecture 그래프 대신 기술 흐름(선행 관계) 모델을 쓴다

- 상태: 채택 (기획 문서 v2의 Architecture → Technology → Concept 그래프를 대체)
- 날짜: 2026-10-11

## 배경
홈을 React Flow 그래프로 만들고, 노드 YAML에 관련 글을 등록하는 구조였다. 운영해 보니 두 가지 문제가 있었다.
1. **연결이 밀렸다.** 글을 쓸 때마다 다른 파일(노드)을 열어 글을 등록해야 했다. 결과적으로 글 5편 중 1편만 연결됐고, 노드 7개 중 6개가 비어 있었다.
2. **독자 경로와 맞지 않았다.** 대부분의 독자는 검색으로 글에 바로 들어온다. 홈 그래프는 텍스트 콘텐츠가 없어 검색 노출에 불리하고, 모바일에서 조작하기 어렵다. 그런데도 모든 방문자가 그래프 라이브러리를 내려받았다.

그 외에 그래프를 접어도 손자 노드가 남는 버그가 있었고, 좌표를 노드마다 직접 적어야 했다.

## 결정
"어떤 기술 다음에 어떤 기술이 오는가"를 데이터의 중심에 둔다.
- 기술은 학습 선행 기술(`requires`)만 손으로 적는다. 분야당 YAML 파일 하나(`src/content/tech/<분야>.yaml`)다.
- 글은 frontmatter `tech: [...]`로 기술에 연결한다. 연결은 글 쪽에서 하므로 글을 쓰는 흐름 안에서 끝난다.
- 화면은 정적 HTML로 만든다.
  - 분야별 로드맵 (`/tech/`)
  - 기술 허브 (`/tech/<id>/`): 선행·다음 기술과 학습 경로 트리
  - 글 하단: 흐름 기준 "이어서 읽기"
- 관계는 트리가 아니라 DAG다. 부모가 여럿일 수 있다(JPA ← Java, SQL).

## 검토한 대안
- **그래프 유지 + 연결 방향만 뒤집기**: 관리 문제는 줄지만 독자 경로와 성능 문제는 남는다.
- **태그/카테고리 목록**: 가장 단순하지만 "다음에 무엇을 배울지"가 표현되지 않는다.

## 결과
- 글 하나를 쓸 때 관리할 곳이 frontmatter 한 줄로 줄었다.
- 카테고리와 태그를 없애고 분류를 기술 하나로 통일했다.
- 기존 `/architecture/*` URL은 없어졌다(리다이렉트 없음, [0001](0001-static-site-on-github-pages.md) 참고).
- 기술 72개를 미리 넣어 두었기 때문에 글이 없는 기술이 많다. 그래서 로드맵은 기본으로 글 있는 기술만 보여주고, 글 없는 기술 페이지는 검색에서 제외(`noindex`)한다.
