# 0002. Jekyll에서 Astro + MDX로 이전한다

- 상태: 채택 (React 관련 부분은 [0005](0005-no-ui-framework-for-widgets.md)로 대체)
- 날짜: 2026-08-26

## 배경
처음에는 Jekyll(Liquid 템플릿)로 시작했다. 글 안에 벤치마크 차트, 코드 비교 같은 조작 가능한 위젯을 넣고, 기술·글·TIL을 연결하는 데이터 구조를 만들 계획이었다. Liquid 템플릿으로는 글 본문에 컴포넌트를 넣기 어렵고, 데이터 검증도 할 수 없다. 당시 글이 1편뿐이라 이전 비용이 가장 낮은 시점이었다.

## 결정
Astro로 이전하고 글은 Markdown/MDX로 쓴다.

- **Content Collections**: 글과 데이터의 형식을 스키마로 정하고 빌드 때 검사한다.
- **MDX**: 글 본문에서 컴포넌트를 바로 쓴다.
- **정적 출력, 기본 JS 0**: 필요한 컴포넌트만 브라우저에서 동작한다.
- **Shiki**: 코드 하이라이트를 빌드 시점에 처리해서 런타임 비용이 없다.

## 검토한 대안
- **Next.js**: 정적 내보내기가 가능하지만 앱 프레임워크라 블로그에는 무겁고, 페이지마다 React 런타임이 따라온다.
- **Hugo**: 빌드는 가장 빠르지만 Go 템플릿이라 글 안 컴포넌트(MDX)가 없다.
- **Jekyll 유지**: 위 배경의 이유로 제외.

## 결과
- 글 URL이 날짜 기반(`/spring/2026/02/16/...`)에서 경로 기반(`/posts/backend/...`)으로 바뀌어 기존 URL은 깨졌다. 색인이나 외부 링크가 거의 없어 감수했다.
- 설정 파일 위치(`src/content.config.ts`)와 Node 22 요구 등 Astro 7 기준을 따른다.
